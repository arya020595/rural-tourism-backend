# Backend Debug Log — 2026-08-04

Debugging session log for the Rural Tourism (RUTeC) Node.js + Express +
Sequelize (MySQL) backend. Documents the bugs diagnosed on this date, their root
causes, and how to reproduce/confirm them. Future debugging sessions should be
recorded in a new `DEBUG_LOG_<date>.md` file rather than editing this one.

> Stack: Node.js + Express, Sequelize ORM (MySQL), JWT auth, Pundit-style
> policies. Conventions in `CLAUDE.md`.

## 0. First moves for any bug

1. **Reproduce the failing request.** Get the exact endpoint, method, and the
   auth token's owner. `console.error` output and thrown `AppError`s are logged
   by `errorResponse`.
2. **Is it data or code?** Before touching code, run the query the endpoint runs
   directly against the DB (see §2). Most "the API returns nothing" reports are
   data/scope issues, not code bugs.
3. **Confirm which DB the API is actually using.** The server reads
   `DB_HOST` / `DB_PORT` / `DB_NAME` from `.env`. A very common false alarm:
   inspecting one database in a client while the API points at a different one.
   Always confirm the `.env` DB matches the DB you're inspecting.

## 1. "API returns nothing" — scoped queries

Many list endpoints are **association-scoped** or **company-scoped** — they only
return rows tied to the caller. An empty result usually means the *caller's*
scope doesn't match the data, not that the data is missing.

**Real case:** the package-company dropdown
(`GET /api/companies/package-options`) returned nothing for an operator.

**How the query works** (`companyService.getCompaniesByAssociationId`):
```sql
-- companies belonging to operators who share the caller's association
SELECT DISTINCT company_id FROM users
WHERE association_id = <caller.association_id> AND company_id IS NOT NULL;
```
Then loads the `companies` for those ids.

**Diagnose (run each SELECT separately in your SQL client):**
```sql
-- 1. What association is the logged-in operator in?
SELECT id, username, association_id, company_id, role_id
FROM users WHERE username = '<login_username>';

-- 2. How many companies does that association have? (the dropdown's source)
SELECT association_id, COUNT(DISTINCT company_id) AS linked_companies
FROM users WHERE company_id IS NOT NULL
GROUP BY association_id ORDER BY association_id;

-- 3. Do the company rows exist?
SELECT id, company_name, association_id FROM companies ORDER BY id;
```

**Interpreting:**
- Query 1 `association_id` is **NULL** → the endpoint throws
  `ForbiddenError("Association scope is required")` (see
  `companyController.getPackageCompanies`). Fix: assign the operator an
  association.
- Query 2 shows **0** for that association → no linked companies; fix the data
  (`UPDATE users SET company_id = ... / association_id = ...`).
- Both look fine but the API still returns empty → it's **not** the DB. The
  token may not carry `association_id`, or the frontend fails after receiving the
  data (check the frontend guide §1 — a client-side cache exception can hide a
  perfectly good response).

**Model note:** the query uses `UnifiedUser` → `tableName: "users"` (not
`rt_users`). Confirm you're inspecting the `users` table.

## 2. Reproduce a query the way the API runs it

Don't guess — run it. Quick throwaway using the app's own Sequelize config:
```js
// node -e "..."  (or a scratch file)
const { Sequelize } = require('sequelize');
require('dotenv').config();
const s = new Sequelize(process.env.DB_NAME, process.env.DB_USER,
  process.env.DB_PASSWORD,
  { host: process.env.DB_HOST, port: process.env.DB_PORT || 3306,
    dialect: 'mysql', logging: false });
(async () => {
  const [rows] = await s.query('SELECT ...');
  console.log(JSON.stringify(rows, null, 2));
  await s.close();
})();
```
This runs against the **exact DB the API uses** (it reads the same `.env`), which
also settles any "wrong database" doubt.

## 3. 401 / 403 — auth and permissions

**401 on login:**
- Wrong credentials for *this* database. Seed passwords differ per environment —
  don't assume `operator_seed`/`operator123` exists locally. Query `users` for
  real accounts.
- Username/email match is **case-sensitive** by design
  (`authService.loginFromUnifiedUsers`). `Admin@x.com` ≠ `admin@x.com`.

**403 on a resource route:**
- The route's `authorize("perm:code")` middleware rejected the token's
  permissions. See `docs/RBAC_ROUTE_PERMISSION_MATRIX.md` for the full map.
- **Stale token:** permissions are in the JWT, minted at login
  (`authService` builds `tokenPayload.permissions`). Changing a role in the DB
  does not affect an active session — the user must re-login.
- Note: some routes have **no** `authorize` (only `authenticate`), e.g.
  `/companies/package-options`. A 403 from those comes from in-controller checks
  (like the association-scope `ForbiddenError`), not the permission middleware.

**Token payload gotcha:** optional claims are only added when present:
```js
if (user.association_id) tokenPayload.association_id = user.association_id;
if (user.company_id)     tokenPayload.company_id = user.company_id;
```
If `req.user.association_id` is undefined at runtime but the DB row has it, the
running build may predate this code (redeploy) or the login loaded a stale user.

## 4. PDF generation (receipts & booking confirmation)

PDFs are generated server-side with Puppeteer from HTML templates in `utils/`:
- `bookingPdfGenerator.js` — booking / deposit receipt (activity, accommodation,
  **and package** — the template branches on `bookingType`)
- `receiptActivityPdfGenerator.js` — activity payment receipt
- `receiptAccommodationPdfGenerator.js` — accommodation payment receipt
- `receiptPackagePdfGenerator.js` — package payment receipt

**Key points when debugging PDF content:**
- **The PDF is independent of the on-screen receipt page.** Editing the frontend
  page does not change the PDF. Fix the generator here too.
- **Data source:** `bookingsService.getReceiptPdfData()` /
  `getBookingPdfData()` decide which fields the PDF shows. If the PDF shows a
  different value than the page (e.g. a different date), it's reading a different
  field. Receipt-issued date resolves as
  `receipt_created_at → updated_at → created_at`.
- **Whole booking type shows blanks:** the template is likely missing a branch
  for that `bookingType`, *and/or* the data method didn't fetch its data. Real
  case: package bookings rendered an empty `AKTIVITI/ACTIVITY` because
  `bookingPdfGenerator.js` had only accommodation vs activity branches, and
  `getBookingPdfData` didn't load `packageItems`. Fix = add the type branch in
  the generator **and** fetch its data (`BookingPackageCompany` rows) in the
  service. Check both sides.
- **Layout:** the detail grids are `grid-template-columns: 1fr 1fr` filled by
  **source order** (some use explicit `grid-column`/`grid-row`). Reordering rows
  = reordering the HTML (or the explicit positions).
- **Month names:** each generator has its own `MONTHS_MY` array. Use full Malay
  names (Januari, Julai, Ogos…), and change every generator, not just one.
- **After editing a generator, restart the backend** — templates are loaded at
  require time; a running server serves the old template.
- **Verify a generator loads:** `node -e "require('./utils/xPdfGenerator.js')"`.
- **Tests:** `npx jest tests/unit/routes/bookingPdf.test.js`.

## 5. Migrations & deploy

- Migrations run on deploy. A failing migration blocks the deploy — see
  `docs/DEPLOYMENT_MIGRATION_GUIDE.md`.
- There is a CI migration check (`.github/workflows/ci.yml`) that runs
  migrations against a clean DB; a red check there means a migration is broken
  before it reaches production.
- **Symptom of a stale production build:** code paths that clearly exist in the
  repo behave as if absent (e.g. a token missing a field added in a recent
  commit). Confirm the deployed commit matches the branch, and redeploy.

## 6. CORS / connectivity (esp. from the mobile app)

`server.js` sets the CORS allowlist **only when `NODE_ENV=production`**; in
dev it is `*`. The production allowlist includes `capacitor://localhost` and
`http://localhost` for the APK. If the mobile app's requests are blocked:
- Confirm the production server runs with `NODE_ENV=production` (otherwise the
  allowlist branch — including the capacitor origins — is inactive... though in
  dev `*` allows everything, so this bites in production-like setups).
- Confirm the frontend's `environment.native.ts` URL/port matches where the API
  actually listens.

## Quick reference: symptom → likely cause

| Symptom | Likely cause | Where |
|---|---|---|
| List endpoint returns empty | caller's association/company scope doesn't match data | §1 |
| "Returns nothing" but data looks present | wrong DB (`.env` mismatch), or frontend cache exception | §0, §1 |
| 401 on login | wrong creds for this DB, or case-sensitive identifier | §3 |
| 403 on a route | missing permission, stale token (re-login), or in-controller scope check | §3 |
| PDF content wrong / differs from page | separate generator, different data field, needs restart | §4 |
| Recent code behaves as if absent | stale deploy / migration failure | §5 |
| Mobile app requests blocked | CORS / NODE_ENV / native URL | §6 |
