## 3. New: Sebut Harga / Quotation module

Full reference: **`docs/QUOTATION_MODULE.md`**. In short:

- Tables `quotations`, `quotation_items` and column `companies.quotation_terms`
  (migrations `20261029100000-create-quotations.js`,
  `20261030100000-add-quotation-terms-to-companies.js`).
- Permissions `quotation:read/create/update/delete` (delete = "Cancel
  Quotation"); operator_admin all, operator_staff all but cancel.
- `/api/quotations`: list (search, status, created-date range), create, view,
  edit, cancel, PDF, booking draft, company default terms.
- Statuses: **Sent** (on save — no draft), **Cancelled**, **Accepted** (when
  converted), **Expired** (computed from `valid_until`, still editable).
- Conversion to a booking or a paid receipt through the normal
  `POST /api/bookings` with `quotation_id` (§4).
- Quotation PDF with the shared Puppeteer browser.

Decisions made along the way (all reflected in the code and the doc): no draft
or delete; title "QUOTATION / SEBUT HARGA" on the PDF; no Sub Total line;
Prepared By is typed (not the login name) and pre-fills Operator Name on
conversion; list shows and filters by **created date**; companies can save
their own default notes & terms.

The earlier planning docs (`docs/design/QUOTATION_PLAN.md`,
`QUOTATION_TECHNICAL.md`) and the quotation mockups were **removed** — they
described draft / delete / mark-as-sent, which were dropped. The as-built doc
replaces them.

## 4. `createBooking`: link a quotation in the same transaction

`services/bookingsService.js → createBooking`, when the body has
`quotation_id`:

1. after the idempotency early-return, lock the quotation row and check it
   (`quotationService.lockForConversion`: exists → 404, same company → 403,
   still `sent` and not linked → 409);
2. create the booking as before;
3. mark the quotation `accepted` with `booking_id` (`markAccepted`);
4. commit.

`quotationService` is required lazily inside `createBooking` (it requires
`bookingsService` itself). `validators/bookingValidator.js` accepts an optional
positive-integer `quotation_id`. Requests without it behave exactly as before.

## 8. Noticed, not changed

`POST /api/bookings` returns **200 "Booking already exists (idempotent)"** for a
*new* booking whenever an `idempotency_key` is sent — the controller compares
the request key with the created booking's key, which is always equal. The
booking is created correctly; only the status code / message is misleading.
Worth fixing separately (check `existing` from the service instead).
