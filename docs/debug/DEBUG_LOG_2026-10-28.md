## 4. Admin dashboard: pending count and booking deposit

`services/dashboardService.js` `getAssociationStats` adds two figures per
association, and adds them to `totals`:

```sql
COALESCE(SUM(b.id IS NOT NULL AND b.status NOT IN ('paid', 'cancelled')), 0) AS totalPending,
COALESCE(SUM(CASE WHEN b.status <> 'paid' THEN COALESCE(b.total_deposit, 0) ELSE 0 END), 0) AS totalDeposit,
```

- **Total Booking Deposit** = deposits on bookings that are **not paid**
  (pending + cancelled). Paid bookings count towards revenue instead.
- These feed the redesigned admin dashboard (frontend log §2).

## 6. Registration with documents failed on production ("Upload was interrupted")

**Symptom:** at the operator onboarding on 2026-10-27, participants who
attached documents (logo, MOTAC licence, trading licence, homestay
certificate) could not register. Some saw "Upload was interrupted. Please
check your connection and try again." Registering **without** documents
worked. Staging had no problem.

**Root cause:** a server setting, not the code. On the shared production
server, every request passes through the host's own nginx
(`nginx/1.18.0 (Ubuntu)`, `/etc/nginx/sites-enabled/`) before Docker:

```
Phone → Cloudflare → host nginx → backend container (127.0.0.1:3008)
                               → frontend container (127.0.0.1:8081)
```

- The production site files `api.rutec.my` and `rutec.my` had **no
  `client_max_body_size`**, so nginx used its default of **1MB** per request.
  Anything bigger was rejected with `413 Request Entity Too Large` before it
  reached Express.
- The staging files (`staging-api.rutec.my`, `staging.rutec.my`) already had
  `client_max_body_size 20m;`, so the problem never appeared in testing.
- The app allows 5MB per file and 20MB in total since 2026-08-13 (`f88c40f`).
  The old limit was 1MB per file, which matched the server default by
  accident and hid the missing setting. The Play Store deployment plan
  (frontend `docs/PLAY_STORE_DEPLOYMENT_PLAN_2026-08-04.md`) included the
  line, but the production files were created without it.
- When nginx cuts the connection mid-upload, the phone can report it as an
  interrupted upload rather than "too large", which matches the message
  participants saw. The backend's own "Upload was interrupted" message comes
  from Busboy's `Unexpected end of form` (`server.js`, see
  `DEBUG_LOG_2026-09-30.md` §3).

**How it was found:** sent test uploads to production as a request **without
`user_type`**. The controller rejects that with 400 after Multer has
received the files, and before any account is created or file is saved. A
`400 Invalid user_type` means the files reached the backend.

| Upload | Before | After |
|---|---|---|
| 0.9MB | 400 (reached the backend) | 400 |
| 1.1MB / 3MB / 4.5MB | **413 from nginx** | 400 |
| 4 files, 18.8MB total | — | 400 |

**Fix (on the server, 2026-10-28):** added `client_max_body_size 20m;` under
`proxy_pass` in both production site files, then
`sudo nginx -t && sudo systemctl reload nginx`:
- `/etc/nginx/sites-enabled/api.rutec.my` (after `proxy_pass http://127.0.0.1:3008;`)
- `/etc/nginx/sites-enabled/rutec.my` (443 block, after `proxy_pass http://127.0.0.1:8081;`)

Backups were saved as `~/nginx-api.rutec.my.bak` and `~/nginx-rutec.my.bak`.
Re-tested both domains afterwards (table above). The same limit also affected
company profile uploads (logo and documents), which are fixed by the same
change.

**Gotchas:**
- The server hosts other projects (dofi, intentharvest, idssurvey). Set the
  limit **per site**, not in `/etc/nginx/conf.d/`, which would change their
  limits too.
- Use `sed -i --follow-symlinks` (or edit `sites-available/`). Plain
  `sed -i` on a `sites-enabled` symlink replaces the link with a copy.
- `sudo nginx -T` prints the full active config. It is the quickest way to
  see which file serves which domain.
- **Edge case:** 20m leaves almost no room above the app's 20MB total. Four
  files of almost exactly 5MB each, plus the form fields, could still get a
  413. Raise to 25m on both production and staging if that ever happens.

The frontend now shows these errors as a pop-up (frontend log §3).

## 11. Package items get their own type and dates

**Request:** each item in a package (an activity or an accommodation at one
of the association's companies) needs its own date, so calendars show when
the customer actually comes. Before, a package had only one date: the one
entered on the package form.

**Migration `20261028120000-add-dates-to-booking-package-companies.js`**
adds to `booking_package_companies`:
- `product_type` ENUM('activity','accommodation');
- `activity_date` DATETIME, stored "as typed" like `bookings.activity_date`
  (date + optional time);
- `check_in_date`, `check_out_date` DATE (accommodation items);
- indexes `idx_bpc_referee_activity_date` (`referee_id`, `activity_date`)
  and `idx_bpc_referee_check_in_date` (`referee_id`, `check_in_date`).

All columns are nullable. Older items have no dates, and the calendar falls
back to the package's own date for them. Ran on the **local** database and
round-tripped (undo + redo). **Production and staging still need
`db:migrate`** (deploy the backend first).

**Service (`services/bookingsService.js`):**
- `normalizePackageItemDates(item)`: parses the type and dates, checks
  they're valid, keeps only the dates that belong to the type, and requires
  check-out **after** check-in (at least one night). Dates are **optional on
  the server**: app 1.0.8 doesn't send them, and rejecting would leave its
  offline bookings stuck. The app requires them (frontend log §9).
- Both places that rebuild package items (create, update) save the new
  fields. `serializePackageCompany` returns `product_type`, `activity_date`,
  `check_in_date`, `check_out_date`.
- **Booked dates** (`getBookedDates`, the "Ada tempahan" marks in the date
  pop-up):
  - a package whose items have dates is marked on those dates, not on the
    package's own date;
  - older packages keep their own date;
  - package items the company provides (`referee_id` = company), including
    referrals from other companies, are added.

Tested against the local API: invalid stays rejected; a 7:30 PM activity was
saved as typed; each company's booked dates came out right.

## 16. Dashboard: each company counts only its own share of packages

`services/dashboardService.js` (Today + Trend, cards and charts).

**Bug:** for a company,
- packages it created counted at the **full package total**, including
  other companies' items;

  `...Monthly`) uses items with `referee_id` = company, in its own and
  referred packages. Revenue = sum of `per_price`. Each package counts once
  for receipts and tourists. Monthly variant for the trend charts.
- Superadmin unchanged.
