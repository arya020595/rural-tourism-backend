# Debug / work log — 2026-11-04

## 1. Association Statistics missing from the association menu on staging

**Symptom:** after merging to `develop`, the KTA association admin on
`staging.rutec.my` saw only *BI Dashboard*, *Registration Approvals* and *Account
Settings*. The new *Statistik Persatuan / Association Statistics* item was missing.

**Cause:** the menu item (frontend `menu.service.ts`) and the two backend endpoints
(`GET /api/dashboard/my-association-stats`, `/my-association-members/:companyId`)
need `association:read`. Seeder `20260423000003-update-association-role-permissions.js`
had reduced the association role on staging/production to `bi_dashboard:read`
(plus `registration:approve` from the registration approval migration). Local
databases still had the old full set, so it worked during development, and
`ASSOCIATION_STATISTICS.md` wrongly said no migration was needed.

**Fix:** migration `20261104000000-grant-association-read-to-association-role.js`
gives `association:read` back to the association role (self-contained: creates the
permission if missing; `down` removes only the association role's grant).
`association:read` unlocks nothing else on the backend: both endpoints are limited
to the user's own association and approved member companies.

**Tested on the local MySQL:** up with the grant already present (no error), down
(grant removed, i.e. the staging situation), up again (grant back).

**Staging was fixed by hand first:** `association:read` was ticked for the association
role in *Role Management*, and the page appeared. The migration is still kept so
production gets the permission on deploy without anyone having to remember it; on
staging it does nothing (`INSERT IGNORE`).

**After deploy:** association users must log out and in again; the menu reads the
permissions from the login response.

Also fixed: a stray `the w` typed into the header comment of
`20261030130000-add-registration-approval.js` (comment only).
