## 2. New: registration approval

Full reference: **`docs/REGISTRATION_APPROVAL.md`**. In short:

- **Statuses:** `companies.registration_status` is pending / approved /
  rejected, with four companion columns. Existing companies default to
  approved.
- **Sign-up:** operators must choose an association and start pending.
- **Login:** pending and rejected companies get a 403 with a `code`, and their
  logged-in users get a 401 on the next request.
- **API:** `/api/registrations` (list / counts / detail / approve / reject),
  permission `registration:approve` for the association role, with a
  same-association policy.
- **Notifications:** bell notification to the association's users and
  superadmins; emails to the operator on each decision.
- **Hidden until approved:** companies that aren't approved are left out of
  the company pickers, quotation items and association stats.

## 3. Pre-existing bug: bell notifications failed to insert

**Symptom.** Registering an operator saved the company, but the approvers'
notifications failed with a duplicate key error.

**Cause.** The first version of
`20260518000001-add-unique-index-to-notifications` called `addIndex(...,
{ where })`. MySQL has no partial indexes, so Sequelize silently created a
**table-wide** unique key on `(type, related_id, created_at)`. Two
notifications of the same type about the same record in the same second
(several approvers) collided. The migration was rewritten later, but databases
that had already run it kept the bad index; the local DB was one of them.

**Fix.** `migrations/20261030140000-repair-notifications-reminder-index.js`
drops that index only if it is the old one, and recreates the intended
reminder-only index on the generated column `reminder_dedupe_key`.

## 4. Changes after the first build (user feedback)

| Change | Why |
|---|---|
| The association shows the three statuses as **Pending / Active / Inactive**. Reject from active is offered as **Deactivate**, and approve from inactive as **Activate** | associations need to switch members off and on, not only decide new registrations |
| Login, session and duplicate sign-up messages for `rejected` now say "account inactive" instead of "registration rejected" | the same status now also means "deactivated" |
| New email `sendCompanyDeactivatedEmail`; `decide()` returns `previousStatus` to choose between the "rejected" and "deactivated" emails | a deactivated member shouldn't get a "registration rejected" email |
| 409 messages say "already active" / "already inactive" | match the new wording |
| Decision emails are **sent in the background** (`void sendDecisionEmail(...)`) | Gmail SMTP took ~4.4 s, so the app's spinner stayed up after every decision. Emails were already best effort |

## 5. New: association statistics for association users

Full reference: **`docs/ASSOCIATION_STATISTICS.md`**.

- `GET /api/dashboard/my-association-stats` returns the superadmin
  association figures for the caller's own association, plus its approved
  members.
- `GET /api/dashboard/my-association-members/:companyId` returns a member's
  profile.
- `getAssociationStats` gained an optional `associationId` filter; the
  superadmin page is unchanged.
- Per member, the API returns **tourists** (pax of paid bookings) only.
  Revenue and booking counts were removed on request.
- `totalDeposit` is now also split into **`totalDepositPending`** and
  **`totalDepositCancelled`** (pending + cancelled = total), so the page can
  show deposits from cancellations separately. Both fields are also on each
  association row and in the totals of the superadmin endpoint (additive, the
  superadmin page doesn't show them yet). Local KTA: RM 623.00 + RM 250.00 =
  RM 873.00.

## 6. Email sender

- `.env` locally now sends as **`"RuTEC Sabah <rutecsabah@gmail.com>"`** with
  a Gmail app password. The SMTP login was checked with `transporter.verify()`.
  `.env.example` was updated to show the display-name form.
- **Why mail went to spam:**
  - it was sent from a personal Gmail address with no reputation;
  - the login link was `http://localhost`;
  - there was no sender name;
  - the content was short "approved / deactivated + link".
- The lasting fix is sending from `noreply@rutec.my` through a provider such as
  Brevo, with SPF, DKIM and DMARC. It's a DNS + `.env` change by whoever
  manages `rutec.my`, so it isn't done yet.
